# 金币收集项目学习计划

## 目标与当前起点

通过完成一个可玩的 Three.js 金币收集 DEMO，练习 Git/GitHub、JavaScript、浏览器事件、前后端 API 和验证方法。随后迁移到 TypeScript，并体验自动检查与部署。

截至 2026-09-14，代码已包含场地、静止玩家方块、画布尺寸适配和 `/api/health` 健康检查。依赖存在，Codex 已执行前端构建与前后端 JavaScript 语法检查并通过。尚未在本轮验证浏览器画面和实际前后端连接；项目没有初始化 Git。玩家移动、金币、倒计时、成绩保存、排行榜、TypeScript 和 CI/CD 尚未实现。以上是项目状态，不代表学习者已掌握这些内容。

## 学习节奏

建议每次 30–45 分钟，一个小目标可跨多次对话；整条路线约 18–26 次练习，按实际理解调整，不以时间判定完成。

每个小目标按“预测并说明原因 → 自己操作 → 比较实际结果 → 用自己的话修正解释”推进。Codex 每轮只提出一个核心问题或操作任务；先提供必要的语法与命令示例，不要求猜陌生 API。卡住时逐步增加提示，明确要求直接解释或代做时直接完成。

功能验收和理解验收分别记录。独立验证要求解释机制并完成一个适当的变化练习；只说“懂了”或运行成功不足以标记掌握。

## 分阶段路线

| 阶段 | 建议次数 | 学习内容与项目任务 | 功能或操作验收 | 理解验证示例 |
| --- | --- | --- | --- | --- |
| 1. 运行与 Git/GitHub 起步 | 2–3 | 启动前后端；认识 npm scripts、工作区、暂存区、提交和远程；亲自初始化、首次提交、连接 GitHub 并推送 | 页面显示场地和 API 连接；本地提交与远程文件可核对 | 解释暂存后再次修改文件时提交记录哪个版本，用差异输出验证 |
| 2. JavaScript 与场景代码 | 2 | 在现有代码中认识变量、对象属性、函数、参数、模块和 DOM；修改玩家颜色、位置或场地大小 | 小修改可观察且构建通过；形成一次可说明的提交 | 预测位置属性变化的画面效果，并独立完成相近修改 |
| 3. 键盘输入与玩家移动 | 2–3 | 事件、按键状态、条件判断、逐帧更新、时间差和移动边界；从单方向移动逐步扩展 | 玩家可用方向键或 WASD 移动、松键停止且不越界；按键不干扰页面滚动 | 解释一次按键事件和持续按键状态的区别，预测不同帧率下移动的变化 |
| 4. 金币与计分 | 2–3 | 数组、遍历、函数拆分、位置距离、碰撞与场景对象移除 | 玩家接近金币时收集；同一金币只计分一次；有可见分数 | 独立追踪一次收集如何同时改变数据、场景和分数，验证重复计分边界 |
| 5. 倒计时与游戏状态 | 2 | 时间计算、状态切换、开始与重开、UI 更新 | 可以开始、计时、结束、重开；结束后停止移动和计分 | 解释重开需要重置哪些状态，验证连续重开不叠加计时 |
| 6. 成绩提交 API | 2–3 | HTTP 方法、JSON、fetch、async/await、请求与响应、输入校验和错误处理；逐步加入游戏记录与成绩提交 | 前端能提交一局成绩；后端拒绝无效输入；网络失败时页面给出反馈 | 追踪浏览器到后端的数据流，解释网络失败与非成功 HTTP 状态的区别 |
| 7. 保存成绩与排行榜 | 2 | 先理解内存保存，再引入简单本地持久化；排序、列表渲染、等待与失败状态 | 后端重启后成绩仍在；排行榜按约定顺序显示 | 解释内存与持久化的区别，独立验证排序和空列表情况 |
| 8. 协作流程与 DEMO v1 验收 | 2–3 | 在后续功能中持续练习分支与小提交；本阶段完成 PR、隔离的冲突练习、合并与版本标签；给关键游戏规则/API 加必要检查 | 完整游戏流程通过；GitHub 上有可核对的 PR 和版本标签；运行说明准确 | 解释冲突发生原因并亲自解决一次练习冲突，说明检查能发现和不能发现什么 |
| 9. TypeScript 渐进迁移 | 2–3 | 类型标注、联合类型、接口、空值处理、编译期与运行时的区别；按模块迁移 | 类型检查通过，原有游戏和 API 行为通过验证 | 独立修复一处真实类型问题，解释为什么类型检查不能替代 API 输入校验 |
| 10. CI/CD 与发布体验 | 2 | 使用 GitHub Actions 自动安装、检查和构建；演示失败阻止合并所需配置；选择适合前端和持久化后端的部署方式 | 用户授权的远程配置可核对；练习分支失败与修复可观察；发布后完成整局与 API 检查 | 解释本地通过与远程失败的可能差异，以及前端静态托管和后端运行的区别 |

Git 小提交与分支练习贯穿阶段 2–7。具体框架 API 和部署服务在对应阶段按官方文档核对；本计划不表示远程资源已经创建或部署已获授权。

## DEMO v1 的完成标准

阶段 8 结束时，至少验证以下行为；TypeScript 和 CI/CD 属于后续学习，不阻塞本地 DEMO v1：

- 前后端可按 README 启动，画面与连接正常。
- 玩家可以移动且受场地边界限制。
- 金币可收集、分数正确，无重复计分。
- 有开始、倒计时、结束、重开流程；重开清理上一局状态。
- 可以提交成绩、保存成绩、显示排行榜；非法输入与请求失败有明确处理。
- 关键流程经过实际验证，已知限制写入 README；GitHub 提交、PR 与版本标签可核对。
